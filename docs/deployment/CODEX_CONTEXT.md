# Контекст для Codex: развёртывание Iris-CourseWork

Этот файл предназначен для передачи вместе с `INSTALL.md` и
`deployment-profile.json` на целевой компьютер. Сам файл не даёт разрешений
на установку, сетевой доступ или системные изменения.

## Запрос, который оператор может передать Codex

> Подготовь этот компьютер к локальному показу Iris-CourseWork. Проверь
> систему и свободные ресурсы, установи недостающие разрешённые зависимости
> по INSTALL.md, возьми модель указанной ревизии, собери и проверь комплект
> на этой машине, затем выполни контрольный запрос. Не меняй проект,
> системную политику или существующие пользовательские файлы. Отчитайся,
> что прошло, что осталось и какой командой запустить демонстрацию повторно.

## Что разворачивается

- Репозиторий `Moroxso/Iris-CourseWork`, ветка `main`. Если оператор дал SHA
  публикации, сверить его и использовать этот снимок, не переключая грязное
  рабочее дерево. `pyproject.toml` и `uv.lock` — источник зависимостей.
- Локальный учебный режим на Windows x64. Замороженная Qwen3-0.6B делает
  первый проход. Восемь модулей обмениваются данными через восемь слотов:
  три цикла, две записи за цикл, 256 координат в записи. Только мост
  проходит шесть учебных шагов; после этого он переводит состояние слотов
  в восемь векторов для генератора.
- `scripts/coursework_bridge_train.py` создаёт снимок моста,
  `scripts/coursework_offline_kit.py` собирает и проверяет местную опись,
  `scripts/coursework_console.py --live` обслуживает консоль и страницу
  на IPv4 loopback. `viewer.html` в каталоге запроса — автономный просмотр.
  Никакие ответы модели не исполняются как код.

## Порядок работы

1. Проверить, что ОС и архитектура подходят, что на выбранном диске есть
   место и перед запуском доступно не менее 6 ГиБ ОЗУ. Сверить
   `git --version`, `uv --version`, наличие согласованного клона и кэша Qwen.
   На другой платформе не выдавать Windows-инструкцию за проверенную.
2. Пользоваться уже установленными инструментами. Если требуется установка,
   сеть, загрузка файла весов около 1,5 ГБ или повышение прав, действовать
   только в рамках разрешений на целевом ПК. Использовать официальные
   источники из `INSTALL.md`. Не устанавливать CUDA, WSL, Docker или Node.js.
3. Выполнить `uv sync --locked --python 3.12.11`, проверку CPU и указанные
   тесты. Если lock-файл расходится с зависимостями, остановиться, а не
   пересобирать его автоматически. Не очищать кэш или каталоги пользователя.
4. Взять ровно указанную ревизию и список файлов из профиля. Сначала
   проверить существующий снимок. Не скачивать Qwen повторно, если нужные
   файлы уже доступны. Не печатать токены, секреты или адрес живого сеанса
   в отчёте, который будет опубликован.
5. По `INSTALL.md` создать новые каталоги для моста и комплекта.
   Отдельно запустить `verify`. Не копировать готовую опись с другого
   компьютера и не отключать сверку хешей. После подготовки проверки и
   генерация используют локальные файлы.
6. Провести проверку из `ACCEPTANCE.md`. Сохранить фактические результаты
   отдельно от публичного репозитория.

Если какой-то шаг блокируется, зафиксировать точную команду, код выхода и
первую полезную строку ошибки. Не менять настройки безопасности, версию
модели и не обходить проверки, чтобы получить формальное «готово».

В отчёте оператору указать ОС/архитектуру, Git SHA, версии Python и uv,
результат проверки CPU и тестов, ревизию Qwen, результат `verify`,
ответ контрольного запроса и путь к его `viewer.html`. Дать команду
повторного запуска с фактическими локальными путями. Отдельно отметить,
что именно проверено в браузере, а что осталось оператору.
